# Автономная работа — действующий протокол этапа

Основание: владелец разрешил исполнение `.hermes/plans/2026-09-11_114507-autonomous-mvp1-expert-council.md`. Этот протокол не отменяет protected approvals и pending exact specification approval.

- Источник требований: текущий OpenSpec change, не экспертные мнения и не память.
- Каталог 19 ролей берётся из утверждённого плана. Роли — аналитические контексты, не установленные профили/модели.
- Уточнение владельца: консилиум полного состава E01–E19, не шесть экспертов. Все 19 отдельных read-only контекстов оценивают вопрос со своей стороны; нерелевантность роли отмечается явно. Source lookup → консилиум → минимальный probe → reconciliation; при споре до трёх волн. Ограничение ресурсов — три concurrent processes, каждый timeout 180 секунд; это не ограничение состава. Недостающий ответ отмечается failed/timeout, не придумывается. Штатные настройки Hermes ради последовательных групп не меняются.
- Контекст через stdin, без secrets; no-tools требование и read-only sandbox. Эти ограничения не выдаются за запрет любых file reads средствами sandbox; секретные файлы не включаются в packet.
- Отдельные процессы одной модели не равны независимым моделям. Cross-model в автономном режиме не подключается без отдельного согласования.
- Решение принимается по evidence и контракту, не большинством. Не закрывать gate source trace или stubbed тестом, если требуется live acceptance.
- Blocked gate блокирует только зависимые операции. Сохранять результаты и продолжать независимые разрешённые проверки, не просить «продолжать?» на каждом шаге.
- Уточнение владельца: завершение подэтапа, зелёные тесты, новый отчёт или обновление памяти НЕ повод завершать работу запросом продолжения. Промежуточные evidence сохранять в файлы; не останавливать исполнение ради их демонстрации. Следующий разрешённый шаг выполнять в том же рабочем цикле.
- Повторное уточнение 2026-09-16: публикация промежуточного результата после Linux cleanup была преждевременной остановкой. Даже успешное mine/checkpoint не является концом работы. Перед final отдельно проверить наличие независимого разрешённого следующего действия; при его наличии выполнять его, а не завершать ход обещанием продолжения.
- Технические вопросы и низкую уверенность разрешать через source/probe и консилиум релевантных ролей; при споре применять согласованный трёхволновой процесс. Не эскалировать владельцу выбор алгоритма или уже разрешённую локальную работу.
- Эскалация только при действительной потребности в участии владельца (пароль, авторизация, ручной приёмочный шаг) либо когда требуемое действие выходит за явные границы согласованного scope. Консилиум не выдаёт пароль, owner approval защищённой операции или разрешение нарушить no-core/no-production ограничения. Перед эскалацией исчерпать независимые разрешённые задачи и собрать один точный пакет, не blanket approval.
- Этот протокол задаёт поведение текущего исполнителя, но не гарантирует продолжения после завершения CLI процесса. Не обещать фоновую автономную работу без реально запущенного механизма; ORCH-01 остаётся критическим незакрытым требованием.
- Не изменять Hermes Agent вообще: владелец отклонил core patch, включая локальную копию/fork/monkey patch. Не менять production infrastructure, не обходить native approvals, не создавать custom service, не включать global Hermes YOLO. OSS alternatives research разрешён; выбранный external workflow и изменение Telegram-only scopes требуют отдельного решения владельца. Publisher/merge/destructive scopes сохраняются из интервью до согласованного изменения.
- Авторизации, точные scopes защищённых операций и ручные тесты по всему плану собирать в одну следующую эскалацию через `owner-action-batch.md`; security blocker не скрывать ради пакетирования. Локальный executor scope подтверждён, повторно его не спрашивать. Новое разрешение при необходимости менять настройки Hermes касается настроек для консилиума, не ядра, OAuth или других профилей.
- Перед записью/повтором внешнего эффекта проверить точный target/state; успех CLI сам по себе не remote verification.
- После approved docs edits индексировать только tasks/openspec. Research code не равен runtime implementation; нормативный revision digest не менять из-за ненормативного журнала.
