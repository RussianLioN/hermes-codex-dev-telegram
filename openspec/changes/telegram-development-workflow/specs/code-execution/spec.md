## Purpose

Исполнять инженерные поручения Codex в ограниченной рабочей области и завершать попытки безопасно при ошибках, таймаутах, отмене или потере авторизации.

## ADDED Requirements

### Requirement: TG-05 Scoped and bounded execution
Система SHALL передавать текст задачи как данные, закреплять проверенный base commit, рабочую область, разрешённые команды и бюджеты. Codex SHALL использовать авторизацию по подписке ChatGPT, без автоматического перехода на отдельно оплачиваемый API. Исполняемый проектный код MUST NOT получать управляющую DB, Telegram/GitHub credentials или читать credentials клиента модели; нужный клиенту модели маршрут SHALL быть отделён от сети проектного кода. Реализуемость этой границы при выбранном способе OAuth SHALL быть проверена до admission, а не предполагаться по наличию контейнера. Обычный и YOLO режимы SHALL оставаться внутри выбранного проекта; изменения инфраструктуры требуют владельца в обоих режимах.

#### Scenario: Invalid base or injected command
- **WHEN** base SHA не разрешается в commit либо вход содержит произвольные CLI/env поля
- **THEN** исполнение отклоняется до запуска process и внешних действий

#### Scenario: Missing OAuth or resource budget
- **WHEN** штатная авторизация недоступна или исчерпан разрешённый ресурсный бюджет
- **THEN** отсутствие OAuth блокирует попытку без автоматического login/logout и смены провайдера; нехватка ресурсов оставляет задачу в ожидании без снятия лимитов и остановки чужих сервисов

#### Scenario: YOLO requests host control
- **WHEN** worker в YOLO пытается получить host Docker socket, изменить серверную конфигурацию или чужой проект
- **THEN** операция отклоняется техническими границами окружения, а необходимое инфраструктурное изменение передаётся владельцу штатным способом

#### Scenario: Manual launch has the same boundary
- **WHEN** владелец запускает обычный интерактивный Codex по SSH вместо автоматического запуска Hermes
- **THEN** сохраняются project identity, credential/network isolation, resource limits и запрет host/socket/чужих данных; SSH и YOLO не дают дополнительных инфраструктурных прав

### Requirement: TG-06 Fenced cancellation and recovery
Система SHALL отзывать поколение попытки при отмене и подтверждать остановку всех принадлежащих ей процессов до сообщения «остановлено». Поздний результат старого поколения MUST NOT продвигать задачу или разрешать публикацию.

#### Scenario: Escaped child process
- **WHEN** дочерний процесс пережил остановку родителя или отделился от его session
- **THEN** состояние остаётся unconfirmed/blocked до подтверждённого завершения task containment, а не объявляется cancelled успешно

#### Scenario: Late completion
- **WHEN** после отмены или новой попытки приходит результат прежнего поколения
- **THEN** результат сохраняется только как диагностическое событие и не меняет актуальный статус приёмки
