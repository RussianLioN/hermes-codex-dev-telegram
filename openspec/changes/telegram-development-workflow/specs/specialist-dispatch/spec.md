## Purpose

Назначать задачи Hermes и Codex с ограниченными пакетами контекста и полномочиями, поддерживая параллельных субагентов без смешивания данных владельцев и проектов.

## ADDED Requirements

### Requirement: TG-03 Explicit specialist routing
Система SHALL выбирать исполнителя по типу задачи и разрешённой policy штатными средствами Hermes. Очередь исполнения SHALL оставаться в Hermes Kanban при подтверждённой совместимости; собственная дублирующая очередь запрещена. MVP1 SHALL разрешать параллельные проекты и субагентов с отдельными настраиваемыми лимитами. Название роли или профиля MUST NOT предоставлять права. Полноценная команда специализированных профилей и их общение не являются обязательными для MVP1.

#### Scenario: Unknown specialist
- **WHEN** назначенный профиль отсутствует или не разрешён для проекта
- **THEN** задача остаётся blocked с объяснением, без произвольного shell fallback

#### Scenario: Cross-project access
- **WHEN** специалист проекта A запрашивает контекст или артефакт проекта B без разрешения
- **THEN** запрос отклоняется и исполнение не получает чужие данные

#### Scenario: Parallel writers
- **WHEN** две пишущие подзадачи одного проекта, включая ручную SSH-сессию и автоматическую Hermes-задачу, допущены к исполнению
- **THEN** каждая получает отдельные worktree/ветку и пакет с owner/project/task/spec/base revision, критериями и разрешёнными источниками; общий writable Hermes home не используется, интеграция выполняется последовательно с повторными тестами

### Requirement: TG-04 Compatibility and policy admission
Система SHALL подтверждать совместимость выбранных Hermes/Codex interfaces и применять утверждённую policy/skill revision на всём протяжении run. Установка и обновление общих навыков/инструментов SHALL требовать owner approval и pin версии/commit; совместимость Hermes/Codex SHALL проверяться отдельно. Разрешённые проектные зависимости SHALL устанавливаться автономно внутри проекта без расширения инфраструктурных прав. Неподтверждённый interface или попытка ослабить ограничения MUST блокировать опасное действие.

#### Scenario: Unsupported runtime interface
- **WHEN** установленный CLI отвергает обязательный параметр либо отсутствует необходимый lifecycle callback
- **THEN** задача блокируется до запуска, без смены runtime или отключения sandbox

#### Scenario: Dynamic skill substitution
- **WHEN** worker пытается заменить helper или загрузить неразрешённый skill во время задачи
- **THEN** изменение не вступает в силу и нарушение фиксируется отдельно от результата работы

#### Scenario: Shared extension compatibility
- **WHEN** общие OpenSpec, MemPalace, skills или rules предлагаются для Hermes и Codex
- **THEN** совместимость загрузки и использования подтверждается отдельно для каждого harness/adaptor на закреплённой revision; само наличие общего каталога или одинакового имени не считается поддержкой

#### Scenario: Project extensions remain local
- **WHEN** агент устанавливает разрешённые проектные инструменты, skills или зависимости
- **THEN** установка автономна только внутри данного проекта и не меняет shared toolchain, base image, соседний проект или server permissions; выход за эту границу требует exact owner approval через Telegram
