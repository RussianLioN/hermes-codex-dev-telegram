# B — ограниченный Linux/model canary после native source проверки

Статус: PROPOSED / OWNER_APPROVAL_REQUIRED / NOT_DEPLOYMENT. Дата: 2026-09-16. ORCH-01 / CRITICAL открыт.

Это новый scope, не повторное использование прежнего «+». `local-linux-canary-scope.md` разрешал одну уже удалённую VM и исключал проектный model turn. Подтверждение B необходимо до создания следующей инфраструктуры. Оно не закрывает CLIENT_ROUTING_GATE_OPEN и не разрешает production deployment.

## Цель и основание

Следующее необходимое runtime свидетельство — настоящий model tool в credential-free Linux executor, а не успешный thread/start или синтетический ответ модели. Локальный подготовительный пакет: `native-environment-evidence.md`, `council/environment-admission/decision.md`; текущие фактические probes — `environment-run/receipts-v4.json`.

Native CLI предоставляет путь без копирования OAuth: `codex exec --ignore-user-config` оставляет штатный auth в CODEX_HOME, но использует EnvironmentManager::from_env; CODEX_EXEC_SERVER_URL выбирает remote без local. Source: pinned `codex-rs/exec/src/cli.rs:39–45`, `exec/src/lib.rs:329–358,530–540`. Это исследовательский CLI путь, НЕ готовая интеграция Hermes transport.

Важные ограничения: ignore-user-config не отключает system/cloud/managed/project layers; profile-v2 наслаивается на base user config, а не заменяет его. managed policy может иметь приоритет над CLI. Эти случаи нельзя считать изолированными по одному флагу. Model stage ниже условный: при невозможности безопасно проверить фактический bootstrap/config/tool surface он НЕ выполняется. Этот scope не разрешает обходить managed policy или читать значения секретов для её исследования.

## Разрешаемые действия — один пакет

1. Создать ровно одну новую временную Colima VM `hermes-boundary-model-canary`. Имя до создания должно отсутствовать. Не использовать/удалять существующий одноимённый профиль; не запускать default VM, не менять Docker context или пользовательский SSH config.
2. VM: aarch64, 1 vCPU, 2 GiB RAM, data disk 8 GiB, root disk 10 GiB; startup timeout 600s, исследовательское окно не более 45 минут после readiness. Без home/project mounts, SSH-agent forwarding, Kubernetes, Rosetta/binfmt, публичного IP/публичных портов и автоматического port-forwarder. Стартовые флаги — как в предыдущем проверенном scope, но с НОВЫМ именем.
3. Перед configuration/dependency work выполнить существующий private backup wrapper без чтения/вывода/индексации archive payload. Разрешена штатная bootstrap загрузка официального base image Colima при cache miss, с фиксацией source/version/hash. Никаких host package upgrades или новых зависимостей Hermes.
4. Использовать уже скачанный официальный Codex 0.153.4 Linux aarch64 bundle только после проверки SHA-256 `fc395cb043a1093ab0db34f44aba3199bfaa9ce640cd9be7fd588f44b0da64a4` и archive paths/links. Распаковать только в новую VM. Проверить installed macOS Codex hash `b973d440acac501fd2594a43e7ca9ce41e0a65b9dfb28d0d7a7837c99e1261e3` перед model stage. При несовпадении не обновлять pins автоматически.
5. Внутри только этой VM разрешён trusted root setup: собственные fixture directories, отдельный непривилегированный UID/GID, cgroup v2 с `memory.max=536870912`, `pids.max=64`, `cpu.max=25000 100000`, ограниченный project/tmp scratch, права и при необходимости mount/network restrictions. Worker без capabilities, supplementary groups и повышения привилегий; без Docker socket, control credentials и sudo authority. Проверки используют только synthetic protected markers.
6. Для native CLI remote transport разрешён один временный exec-server listener только на loopback внутри новой VM и один принадлежащий этому запуску SSH forward на loopback Mac. Никаких listeners на 0.0.0.0, публичной публикации, remote registration/hub или Agent Identity tokens. Разрешён generated SSH connection config только для -F отдельного owned процесса, без изменения ~/.ssh/config и без копирования ключей. Если безопасное ограничение listener/forward и worker network не доказано — model stage запрещён.
7. В новой VM разрешены только принадлежащие canary network rules/namespace, если они нужны для transport: worker не должен инициировать outbound соединения, включая новые соединения к control listener. Ответы по установленному controller→executor каналу допустимы. Root positive control и worker negative control обязательны; отсутствие маршрута само по себе не доказывает correct policy. Если штатных инструментов недостаточно, не устанавливать новые пакеты и не ослаблять ограничение молча.
8. Выполнить no-auth Linux preflight: реальные native FS/process положительные и отрицательные проверки; UID/caps/env/fd/control-file protections; source/config/mount view; cgroup descendants, включая setsid; bounded kill и external empty readback. Старый boot ID не использовать: новый boot ID и exact owned profile должны быть связаны с creation receipt. Исторические probes/receipts не переписывать.
9. Только после положительного admission разрешён один `codex exec` invocation с существующей local ChatGPT OAuth и gpt-6-astra для заранее фиксированного синтетического задания. Это одна задача, не обещание одного HTTP запроса: штатный tool loop может сделать несколько model API calls. Deadline 120s, общий stdout+stderr cap 1 MiB; без автоматического повторного запуска после failure/unknown. Обычное использование и штатный refresh существующей OAuth остаются на Mac у доверенного native клиента. Не инициировать login/logout/revoke, не читать/печатать/копировать tokens/auth.json, не передавать credentials в VM.
10. Задание модели — только операции над собственным synthetic project: запуск подготовленного диагностического скрипта, чтение worker-only marker, небольшая правка test marker, попытки доступа только к заданным synthetic protected markers. Никакого чтения реальных секретов, текущих repositories или произвольного обзора домашнего каталога. Не использовать --dangerously-bypass-approvals-and-sandbox на клиенте. Native user config/rules и project instructions исключаются поддерживаемыми flags/settings; hooks/plugins/apps/browser/multi-agent и ненужные MCP surfaces не разрешаются. Невозможность доказать эти условия — NO_MODEL_RUN, не основание для ослабления политики.
11. Независимый controller проверяет реальные guest effects, неизменность client/control markers и UID/cgroup, а не доверяет финальному тексту модели. После опыта остановить весь owned executor cgroup, подтвердить отсутствие потомков и отсутствие local fallback/самоперезапуска в проверенном сценарии. Это ограниченный эксперимент, не доказательство всех model tool routes или production resilience.
12. Сохранить source/prompt/config без секретов и фактические receipts/результаты в `.hermes/research/telegram-hermes-codex/native-codex/linux-model-run/`; экспортировать project artifacts безопасно, без следования symlinks в чужие/секретные пути. Не удалять результаты, код, память или спецификации проекта. Затем остановить и удалить только созданную этим scope VM и её технические диски, закрыть owned SSH forward, подтвердить отсутствие exact profile и прежний default/context. Если результаты невозможно сохранить или ownership неоднозначен — не выполнять destructive cleanup молча.

## Stop conditions и недопустимые расширения

- Любой host sudo/password/system-extension запрос, отсутствие безопасной auth, неизвестный активный managed/tool path, неверные hashes/ownership, невозможность cgroup/network/config protection — остановка соответствующей опасной стадии, factual FAIL/NO_MODEL_RUN, без обхода. Разрешённая local/source работа от этого не блокируется.
- Deadline не продлевать автоматически; новую VM или повторный model invocation этим пакетом не разрешать. Не выдавать no-model preflight за выполненный model test.
- Никаких изменений ainetic.tech, Hermes core/default/other profiles, gateway/updater, никаких установок плагинов в рабочий runtime, дополнительных постоянных сервисов, новых аккаунтов/оплат, GitHub creation/push/PR/merge или live Telegram.
- Перед live deployment по-прежнему нужен точный применимый diff/rollback и отдельное подтверждение. Его ещё нет; B не подменяет этот будущий пакет. ORCH-01 / CRITICAL не закрывается данным canary.

Подтверждение владельцем всего B разрешает только перечисленный bounded scope. Этот документ и его hash — ссылка на согласуемый объём, не исполняемый authorization token.
